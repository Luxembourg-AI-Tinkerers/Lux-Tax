## 3. Worth considering

1. **The M4 warning's remedy does not actually include the fact, and the UI has no per-fact include control.** Location: `apps/web/src/lib/fact-inclusion.ts:7-9`, `apps/web/src/components/DocumentsView.tsx:251-256`, `apps/web/src/components/FactsView.tsx` (no row toggle; edit sends only `amount` at `:94-96`), `apps/api/src/modules/documents/documents.service.ts:269-325` (`updateVisibility` only updates the document), `apps/api/src/modules/facts/facts.service.ts:451-483` (`deleteFact` leaves `extractedFact.isConfirmed = true`). Problem: after the warning tells the user to promote the document, `isIncludedInReturn` remains false; the calculation (`calculations.service.ts:74-90`) filters on `isIncludedInReturn: true`, and the confirmed fact cannot be re-confirmed because it stays `isConfirmed`. Impact: a user who follows the warning can still file a return that omits the income; the table shows "Included: No" but there is no action to change it. This is documented as limitation 6 in `impl-review-fixes.md` §4.6, so it is non-blocking here. Suggestion: set `isIncludedInReturn` for the document's confirmed facts when the document is promoted to `PROPOSED_FOR_RETURN`/`INCLUDED_IN_RETURN` (audited), or add a per-fact include toggle in `FactsView`.
2. **The M4 warning text names the wrong cause for a private draft.** Location: `apps/web/src/lib/fact-inclusion.ts:7-9` ("the source document is only shared for discussion"), reachable from `CameraScanModal.tsx:24,143-145` (the user can choose `PRIVATE_DRAFT`) plus `DocumentsView.tsx:251-256`. The API also downgrades `PRIVATE_DRAFT` (`facts.service.ts:242`); the user is told the document is shared when it is private. Impact: misleading but the suggested promotion is still the right action; no data effect. Suggestion: use a generic "not proposed for / included in the return" wording, or pass the visibility to the helper.
3. **`FactsView`'s manual-create success message claims inclusion when the user unchecked "Include in return".** Location: `apps/web/src/components/FactsView.tsx:145-152` and the checkbox at `:484-490`. The request sends `isIncludedInReturn: newFact.isIncludedInReturn` (`:134`); with the box unchecked the API stores false and `factInclusionWarning(false, false)` returns null, so the success toast reads "Added ... to return" while the same row renders "Included: No" (`:384`). Impact: contradictory UI text; the fact is correctly excluded, so no tax or privacy effect. Suggestion: branch the message on `newFact.isIncludedInReturn` (e.g. "Added ... (not included in the return)").
