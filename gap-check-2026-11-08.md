## 2. Gaps found by the check — and fixed

### G1 — 111bis was still capped at €672 on the UI path (material)

`FactsView` presets and demo facts still emitted `INSURANCE_DEDUCTION / pension111bis`. The engine now treats that category as the **Art. 111 €672 envelope**, so a €3,200 third-pillar premium entered through the UI would still have been cut to €672. The engine fix was correct but unreachable from the product.

**Fixed:** the preset list now exposes 22 legal fact types, with `PENSION_SAVINGS_111BIS / art111bis` and `MORTGAGE_INTEREST` as distinct entries; the demo dataset was repointed.

### G2 — questionnaire could not reach several implemented rules (material)

Missing inputs: invalidity rate, épargne-logement subscriber age, 111bis contributors, child allocations, plus-values, foreign treaty row.

**Fixed:** four scalars added to the household grid; an “Gains and foreign income” block adds movable gain (proceeds/cost/months/participation), real-estate gain (proceeds/cost/years/principal-residence) and a foreign row (country/amount/foreign tax). `CalculationsService` maps the single rows into `movableGains`, `realEstateGains` and `foreignIncomeItems`.

### G3 — document extractor contradicted the engine (material)

`receipt-ai-vision.service.ts` matched `prévoyance` and `art 111` in the same branch and always produced `INSURANCE_DEDUCTION`. A scanned pension contract therefore produced a €672 fact.

**Fixed:** a dedicated Art. 111bis branch (prévoyance / 111bis / épargne retraite / PEPP) runs **before** the insurance branch and emits `PENSION_SAVINGS_111BIS`.

### G4 — CISSM was missing entirely

The audit’s P1 list includes the *crédit d’impôt salaire social minimum*; it had no rule, no credit function and no line in the UI.

**Fixed:** `cissm` rule block (1,800–3,000 flat €70/month, linear to 3,600), `cissmForSalary()`, engine wiring, DTO field, calculator row and a test (€2,000/month → €840; €3,300/month → €420; nothing outside the band).
